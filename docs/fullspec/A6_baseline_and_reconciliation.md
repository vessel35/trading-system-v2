# A6 — 처리(폐기·재구축) 인벤토리·대사 결정

> Phase A 분석 산출물. 원천 리포: `trading-system`.
>
> **이 노트가 정하는 것(목적).** 기존 시스템의 각 기능이 신규 backtest 빌드에서 **어떻게 처리되는지**를 네 가지로
> 분류해 확정하고, 그 처리에 능력 공백이 없음을 보이며, 구 backtest와 신 backtest의 수치 대사(reconciliation)를
> 명시적으로 제외하고 사유를 남긴다.
>
> **처리 방법 구분(이 문서의 구성 축).**
> 1. **완전 폐기(대체 없음)** — 기존 기능을 없애고 새로 만들지 않는다. 그 필요가 신규 설계에서 사라진다. → 2절
> 2. **폐기 후 신규 재구축** — 기존 기능을 없애고, 같은 역할을 신규 구현으로 새로 만든다(구 코드를 옮겨오지 않는다). → 3절
> 3. **신규 기능(기존에 없음)** — 기존에 없던 기능을 새로 만든다. → 4절
> 4. **기존 수정·재구성** — 기존 자산을 유지하되 일부를 고쳐 새 시스템에 맞춘다. → 5절
>
> 각 절은 그 구분에 속하는 항목을 **이름·위치와 결정**으로 함께 적는다. 폐기 대상(구분 1·2)은 신규 빌드가 참조하지
> 않으므로 이름·경로로만 식별하고 상세 분석하지 않는다(필드·정책 인용 없음). 신규(3)·유지 수정(4)의 필드·정책
> 상세는 각 상위 인벤토리(지표 인벤토리, 타입·config·DB 인벤토리, 수집기 내재화 범위 인벤토리)와 채택·회귀
> 설계에 있고, 이 노트는 그 처리를 분류하고 결정만 기록한다.

---

## 1. 제약사항·방향

**문서 구성.** 이 노트는 위 네 가지 처리 구분을 축으로 삼는다 — 2절 완전 폐기, 3절 폐기 후 재구축, 4절 신규,
5절 기존 수정, 이어서 6절 대사 제외. 폐기가 기능을 잃게 하지 않는다: 완전 폐기(구분 1)는 그 필요 자체가
신규 설계에서 사라지거나 신규 기능(구분 3)이 대신하는 경우이고, 계속 필요한 기능은 구분 2로 다시 서며, 구분 3·4가
나머지를 채운다. 그래서 폐기로 인한 능력 공백은 없다.

**전면 폐기 서비스.** 구 `services/backtest/`·`services/replay/` 서비스는 전면 폐기한다(재사용 안 함, 참조 안 함).
backtest 서비스의 유효 기능은 구분별로 갈린다 — 엔진·CLI·지표는 구분 2로 재구축(3절), 목 저장소·`sys.path` 스왑·
harness·테스트는 구분 1로 소멸(2절).

**폐기 대상 식별 방식.** 폐기 대상(구분 1·2)은 신규 빌드가 참조하지 않으므로 이름·경로로만 식별하고 코드를 상세
분석하지 않는다(필드·정책 인용이 없다). 유지·수정 대상(구분 4)의 기존 자산 상세는 상위 인벤토리가 이미 식별한다.

**보존 불변식.** 전략·지표 로직을 백테스트용으로 복제하지 않는다(공유 코어 단일 표준). look-ahead·미래 캔들 사용
금지(코어 강제). 이 두 원칙이 구 backtest의 복제 지표·자체 엔진을 구분 2로 폐기·재구축하는 근거다.

## 2. 완전 폐기 — 대체 없음 (구분 1)

기존 기능을 없애고 후속을 만들지 않는다. 그 필요가 신규 설계에서 사라지거나 신규 기능(구분 3)이 당연히 대신하기
때문이다.
- **replay 서비스** (`services/replay/`). 페이퍼 빠른 시뮬 전용. 신규 통합 실행(백테스트·페이퍼·라이브가 공유
  코어 단일 구현을 씀)에서 페이퍼 모드가 그 필요를 대신하므로 전용 후속을 만들지 않는다.
- **`sys.path` 동적 import 경로 조작** (구 backtest, `services/backtest/`). 신규 공유 패키지를 충돌 없는 이름으로 두면
  경로 조작 자체가 불필요하다.
- **구 backtest 목(mock) 저장소·harness·테스트** (`services/backtest/`). 저장소 접근이 주입 포트(구분 3)로 대체되어
  목 스왑 방식은 사라지고, 서비스를 통째로 폐기하므로 그 안의 테스트도 함께 폐기한다.
- **구 집행의 라이브 전용·결함 요소** (실행·비용·사이징 인벤토리에 위치·상술). `PriceCache`·폴링 루프·WebSocket
  핸들러(백테스트는 캔들 구동이라 라이브 가격 피드가 없다), `filled_at=now()` wall-clock 체결 시각, 사후 슬리피지
  경고 게이트. 라이브 전용이거나 결함이라 그대로 되살리지 않는다(올바른 집행 동작은 구분 2에서 새로 만든다).
- **legacy `backtest_db` 잔재 테이블** (아카이브 초기화 스크립트의 구 테이블 + 구 backtest 런타임 생성 테이블, 이름만
  식별). 인벤토리 후 드롭/분리하고 후속 테이블을 만들지 않는다. (backtest_db 데이터베이스·역할 자체는 유지·확장 —
  구분 4와 구별.)

## 3. 폐기 후 신규 재구축 (구분 2)

계속 필요한 기능은 구 코드를 옮겨오지 않고 신규 구현으로 다시 세운다.
- **backtest 엔진·CLI** (`services/backtest/`) **→ 신규 backtest-service.** 구 엔진·CLI를 폐기하고 신규 backtest-service의
  Engine·ConfigLayer·Harness로 새로 선다(구 CLI 카탈로그·스키마는 참조만 하되 서비스 자체는 폐기 — 실행·비용·사이징
  인벤토리 분류와 정합).
- **구 전략 코드·구조 전부** (베이스 클래스·레지스트리·팩토리·파라미터 상속 체인) **→ Protocol + Adaptee, 신규 Adapter
  Manager.** 구 구조를 폐기하고 신규 전략 선택 정책으로 교체한다. 레지스트리·팩토리 기능은 신규 `Adapter Manager`가
  구현 Adaptee 목록을 `signal_db`에 등록·조회하는 것으로 다시 선다(레지스트리 DB 접근은 주입 포트 경유, backtest
  Engine과 signal-service 엔진 공용). 구 레지스트리를 참조해 이식할 필요가 없다.
- **backtest 지표 복제본** (`services/backtest/`) **→ 공유 코어 단일 표준.** 지표 복제본을 폐기하고 82종 지표를
  `core_lib.indicators`로 신규 재구현한다(지표 인벤토리).
- **구 집행 로직** (즉시 체결·gross 회계) **→ 실행 재구현.** 체결 시점을 다음 캔들 시가로, 회계를 net-of-cost로 새로
  구현한다(실행·비용·사이징 인벤토리).

## 4. 신규 기능 — 기존에 없음 (구분 3)

기존 시스템에 없던 기능을 새로 만든다. 여기서는 신규임을 분류하고, 필드·정책 상세는 각 상위 인벤토리와 채택·회귀
설계, 이후 상세 설계에 맡긴다.
- **공유 코어 패키지(`core_lib`).** 충돌 없는 이름의 정식 공유 라이브러리로, backtest·signal·wallet이 단일 표준을 공유한다.
- **주입 포트 기반 저장소 접근.** 구분 1에서 폐기한 목 스왑·`sys.path` 조작을 대체하는 의존성 주입 경계.
- **Evidence 기록 체계.** 원천 데이터·피처·지표 스냅샷과 결정론적 정규화 해시로 재현·감사를 보장한다.
- **`backtest_db` 읽기 전용 역할.** 연구 데이터 분리를 위한 신규 역할 — 타입·config·DB 인벤토리가 "신규 추가"로 식별.
- **자체 검증·통계 검증 기준선.** 결정성·look-ahead 무결성·골든·세 모드 동등성 및 표본 내/외 분리·walk-forward·
  몬테카를로·확률적 샤프 Hard Gate — 채택·회귀 설계가 다룬다(구↔신 대사 제외를 대신하는 검증, Chapter 6 참고).

## 5. 기존 수정·재구성 (구분 4)

기존 자산을 유지하되 일부를 고쳐 새 시스템에 맞춘다. 기존 자산의 식별·상세는 각 상위 인벤토리에 있고, 여기서는
무엇을 유지·수정하는지만 분류한다.
- **signal-service·wallet-service.** 유지하되 공유 코어(`core_lib`)를 채택해 동작 불변으로 재구성한다 — 채택·회귀
  설계가 다룬다. (production은 구현 단계에서만 손대며, 이 설계 단계는 방향만 기술한다.)
- **collector.** OHLCV 적재는 유지하고 지표 사전계산은 폐지한다 — 수집기 내재화 범위 인벤토리.
- **`services/backfill`.** 재사용하여 과거 구간을 확보하고 `ohlcv_futures` retention을 연장(예: 2000일)해 보존한다 —
  수집기 내재화 범위 인벤토리.
- **`backtest_db`·`backtest_writer`.** 기존 생성 자산은 유지하고 메타 필드를 확정하며 읽기 전용 역할을 신규 추가한다 —
  타입·config·DB 인벤토리. (구 런타임 테이블 폐기(구분 1)와 구별: DB·writer는 유지·확장한다.)
- **비밀 저장 방식.** 커밋된 dev 값은 유지하고 저장 방식만 변경한다(신규 비밀만 `.env` 주입) — 타입·config·DB 인벤토리.

## 6. 구↔신 backtest 대사 — 제외 (명시·사유화)

**결정: 구 backtest와 신 backtest가 같은 수치를 내는지 서로 대조(대사)하지 않는다.** 두 결과의 수치가 일치하는지
확인하는 기준선을 두지 않으며, 그 일치를 신 빌드 수용 기준으로 삼지 않는다.

**사유(명시).**
1. **폐기 대상을 참조로 되살리지 않는다.** 구 backtest는 전면 폐기 대상이다. 수치 대사를 만들려면 구 backtest를
   실행하거나 되살려 살펴봐야 하는데, 이는 폐기 결정과 모순되고 폐기 대상 코드를 라이브 참조로 되돌린다.
2. **결함 기준선에 정렬하지 않는다.** 구 backtest는 알려진 편향을 안고 있었다(즉시 체결에 따른 look-ahead·gross
   회계 등, 사유 3에서 신 빌드가 교정하는 항목). 신 빌드의 수용을 구 backtest 수치에 맞추면 정확성이 아니라 결함
   기준선에 검증하는 셈이다.
3. **동작이 의도적으로 다르다.** 신 빌드는 체결 시점을 즉시 체결에서 다음 캔들 시가로 바꾸고, 회계를 net-of-cost로
   교정한다. 구 backtest와의 수치 일치는 애초에 목표가 아니다.

> 이 제외 결정은 신규 Engine 구축 마이그레이션에 들어 있던 "구엔진↔신엔진 대사 run 1회" 진입 게이트로부터의
> **의도적·권한 있는 divergence**다(폐기 대상을 실행해야 하는 그 게이트가 사유 1과 정면 충돌한다). 결정은
> 여기서 명시·사유화하고, 채택·회귀 설계(부록)가 이를 **명시적 수용 기준 문구**로 다시 못박아 downstream에서
> 게이트 변경이 유실되지 않게 한다.

**제외가 "검증 없음"이 아니다 — 대체 기준선.** 신 backtest는 **자체 검증 기준선**을 세운다: 결정성(동일 입력·
seed → 동일 Evidence), look-ahead 무결성 점검, 골든 테스트, 세 실행 모드 동등성(backtest=paper=live가 공유 코어
단일 구현을 씀). 이 자체 검증 기준선은 채택·회귀 설계(부록)가 다룬다(신규 기능 구분 3의 자체 검증과 동일 대상).
이와 **별개로** 재구현된 회계·손익·체결의 **거래소 실측 대비 정확성 골든**(실행·비용·사이징 인벤토리에서 명명)은
제외 대상이 아니다.

구분을 못박는다.
- **제외 대상:** 구 backtest와 신 backtest의 수치가 일치하는지 대조하는 것(구 backtest를 기준선으로 삼는 것).
- **제외 아님:** 신 backtest 자체 검증(결정성·look-ahead·골든·세 모드 동등성) + 지갑 회계 정확성 골든(실측
  대비). 대사 제외가 이들 정확성 검증까지 없애지는 않는다.

## 7. Traceability (설계 표준 요구 ↔ 이 노트 절)

| 이 노트의 절 | 충족하는 표준 요구(이름) |
|---|---|
| 2, 3 | 기존 backtest 서비스·replay·전략 구조 전면 폐기(재사용 안 함), `sys.path` 조작 제거 |
| 1, 2–5 | 각 기능의 처리를 네 구분(완전 폐기·폐기 후 재구축·신규·수정)으로 분류 — 폐기로 능력 공백 없음 |
| 1, 3 | 전략·지표 로직을 백테스트용으로 복제하지 않음(공유 코어 단일 표준) — 계속 필요한 기능은 구분 2로 재구축 |
| 3 | 전략 레지스트리를 신규 Adapter Manager가 재구축(`signal_db` 레지스트리, 주입 포트 경유) |
| 4 | 신규 기능(공유 코어·Evidence·읽기 전용 역할·자체 검증)은 기존에 없던 것으로 분류 |
| 5 | 유지·수정 대상(signal/wallet 채택·collector 적재·backfill 재사용·backtest_db 확장·비밀 저장 방식)을 상위 인벤토리로 위임 |
| 6 | 구↔신 backtest 대사 제외 — 명시·사유화(폐기 대상 비참조·결함 기준선 회피·의도적 동작 변경) |
| 6 | 제외 ≠ 무검증: 신 backtest 자체 검증(결정성·look-ahead·골든·세 모드 동등성) + 회계 정확성 골든은 유지 |

**정합성 확인 대상:** 각 기능이 네 구분(2~5절) 중 하나로 빠짐없이 분류됐는지, 폐기 대상(구분 1·2)이 되살려
분석되지 않고 이름·경로로만 식별됐는지(backtest·replay 코드를 열지 않음), 구↔신 대사 제외가 **조용히 누락되지
않고 명시·사유화**됐는지(세 사유 + 대체 기준선 + "정확성 검증은 제외 아님" 구분), 폐기로 능력 공백이 없음이 구분
2·3·4의 재구축·신규·수정으로 확인됐는지. 이 노트는 채택·회귀 설계(부록)가 재인벤토리 없이 처리 분류·대사 제외를
입력으로 받도록 한다.
