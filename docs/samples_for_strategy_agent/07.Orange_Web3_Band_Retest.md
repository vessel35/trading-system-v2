### 1. 시스템 및 지표 아키텍처 정의

* **기본 주기(Timeframe)**: 5분봉(5m) 차트 기준


* **핵심 지표 구성**:
1. **중앙 추세선 (Center Trend Line)**

* 가격의 중심 추세를 나타내며, 상태에 따라 색상(초록색/보라색)이 변함.




2. **4개의 편차 기반 밴드 (산점도/표준편차 알고리즘 기반)**

* **상단 밴드**: 상단 1차 편차 밴드(점선), 상단 2차 편차 밴드


* **하단 밴드**: 하단 1차 편차 밴드(점선), 하단 2차 편차 밴드




3. **연동형 RSI 게이지 (RSI Gauge)**

* 중앙 추세선 및 4개 밴드와의 비교 분석을 결합하여 상태를 자동 판별.


* **초록색 (과매도 구간)**: 반등/상승 추세 준비 구간 (Long/Buy 신호)


* **보라색 (과매수 구간)**: 조정/하락 추세 준비 구간 (Short/Sell 신호)







---

### 2. 상태 정의 및 노이즈 필터링 조건

* **유효 롱(Long) 환경**:
* RSI 게이지 = 초록색 AND 중앙 추세선 = 초록색




* **유효 숏(Short) 환경**:
* RSI 게이지 = 보라색 AND 중앙 추세선 = 보라색




* **노이즈 및 역패턴 무효화 필터**:
* 색상이 변경되었더라도 캔들의 위치가 비정상적인 경우(예: 과매수 보라색 신호가 떴으나 캔들이 밴드 상단 위로 급등하는 등)는 진입하지 않고 무시(Ignore).


* 캔들이 1차 편차 밴드 안쪽 박스권에서만 횡보할 때는 진입 대기.





---

### 3. 진입(Entry) 알고리즘 로직

단순히 지표 색상이 변했다고 진입하지 않고, **1차 편차 밴드 돌파 + 지지/저항 확인**이 만족될 때 진입합니다.

#### ① 롱(Long) 포지션 진입 조건 (모두 충족 시)

1. **신호 일치**: 중앙 추세선 및 RSI 게이지가 모두 '초록색' 상태


2. **밴드 돌파**: 캔들이 상단(또는 하단) 1차 편차 밴드를 상향 돌파


3. **지지 확인 (Re-test/Support)**:
* 1차 편차 밴드를 뚫은 후, 해당 라인을 **최소 1회(안정성을 높이려면 2회) 이상 지지(N자형 눌림목 반등)** 받는 봉 완성 확인




4. **실행**: 지지 확인 후 재돌파 양봉 완성 시 롱 포지션 오픈



#### ② 숏(Short) 포지션 진입 조건 (모두 충족 시)

1. **신호 일치**: 중앙 추세선 및 RSI 게이지가 모두 '보라색' 상태


2. **밴드 돌파**: 캔들이 1차 편차 밴드를 하향 돌파(음봉)


3. **저항 확인 (Re-test/Resistance)**:
* 1차 편차 밴드에 도달하거나 뚫은 후, 저항/리테스트를 최소 1회 이상 거친 뒤 다시 하향 돌파 확인




4. **실행**: 저항 확인 후 음봉 확정 시 숏 포지션 오픈



---

### 4. 리스크 관리 및 청산(Exit) 로직

자동 매매 구현 시 고정 손익비와 밴드 도달 조건을 결합한 **분할 매도 방식**을 채택합니다.

#### ① 손절가 (Stop Loss)

* **롱(Long)**: 진입 시점 기준 **중앙 추세선(Center Trend Line) 라인 부근** 또는 직전 지지선 하단


* **숏(Short)**: 진입 시점 기준 **중앙 추세선 라인 부근** 또는 직전 저항선 상단



#### ② 익절가 (Take Profit / 분할 청산)

* **기본 손익비 설정**:
* 1차 목표 손익비: **1 : 1.5** (상황/직전 매물대에 따라 최대 1 : 1.7까지 유연하게 설정)




* **분할 청산 단계**:
1. **1차 익절**:
* 1차 목표가 또는 강력한 추세 돌파 발생 시 포지션의 **50% ~ 80% 분할 매도(익절)**



2. **잔여 물량 최종 청산**:
* 남은 20% ~ 50% 물량은 가격 캔들이 **'2차 편차 밴드'에 터치하거나 돌파하는 즉시 전량 매도(100% 완전 청산)**

### 5. 의사코드(Pseudocode) 예시

```python
# 5분봉 캔들 갱신 시 실행
def on_bar_update(bar, indicators):
    center_line_color = indicators.get_center_line_color() # 'GREEN' or 'PURPLE'
    rsi_gauge_color = indicators.get_rsi_gauge_color()     # 'GREEN' or 'PURPLE'
    band_1st = indicators.get_1st_deviation_band()
    band_2nd = indicators.get_2nd_deviation_band()
    center_line = indicators.get_center_line_price()

    # --- 포지션 청산 로직 ---
    if current_position.type == 'LONG':
        # 1. 손절 조건
        if bar.close < center_line:
            market_close_all()
            return
        # 2. 1차 익절 (1:1.5 손익비 도달 시)
        if not current_position.partial_tp_done and bar.high >= current_position.tp_price_1:
            market_close_partial(ratio=0.80) # 80% 부분 익절
            current_position.partial_tp_done = True
        # 3. 최종 익절 (2차 편차 밴드 도달 시)
        if bar.high >= band_2nd.upper:
            market_close_all() # 잔여 전량 매도
            return

    elif current_position.type == 'SHORT':
        # 1. 손절 조건
        if bar.close > center_line:
            market_close_all()
            return
        # 2. 1차 익절
        if not current_position.partial_tp_done and bar.low <= current_position.tp_price_1:
            market_close_partial(ratio=0.80)
            current_position.partial_tp_done = True
        # 3. 최종 익절
        if bar.low <= band_2nd.lower:
            market_close_all()
            return

    # --- 포지션 진입 로직 (무포지션 상태일 때) ---
    if current_position.is_empty():
        # Long 진입: 그린 신호 + 1차 밴드 돌파 후 최소 1~2회 지지 확인
        if rsi_gauge_color == 'GREEN' and center_line_color == 'GREEN':
            if check_break_and_retest(bar, band_1st.upper, direction='BULLISH', min_tests=1):
                sl_price = center_line
                tp_price = bar.close + (bar.close - sl_price) * 1.5
                open_long(sl=sl_price, tp1=tp_price)

        # Short 진입: 보라 신호 + 1차 밴드 돌파 후 리테스트 확인
        elif rsi_gauge_color == 'PURPLE' and center_line_color == 'PURPLE':
            if check_break_and_retest(bar, band_1st.lower, direction='BEARISH', min_tests=1):
                sl_price = center_line
                tp_price = bar.close - (sl_price - bar.close) * 1.5
                open_short(sl=sl_price, tp1=tp_price)

```

## 6. 원문이 비워 둔 값

이 절과 7절은 전략 작성 Agent가 썼다. 결론을 먼저 적는다. **이 전략은 지금의 플랫폼에서 원문대로도,
일부로도 만들 수 없어 구현하지 않았다.** 막는 것은 원문 1절이 정의한 세 지표 구성 요소(중앙 추세선,
4개의 편차 기반 밴드, 연동형 RSI 게이지)가 registry에 없고, 원문 서두가 밝히듯 계산식도 받은 글에 없다는
사실이다. 원문 2절의 환경 정의, 3절의 진입 조건 넷, 4절의 청산 조건 셋이 모두 이 세 구성 요소의 값을
읽으므로, 그것 없이 표현할 수 있는 규칙은 timeframe 하나뿐이다. 지표를 등록하는 일은 계산 표준을 먼저
갖추는 플랫폼 작업이며(규범 `docs/strategy-authoring-contract.md`의 4.7절과 6.1절), 전략이 그것을 다른
지표로 흉내 내지 않는다.

아래 6.1절은 원문이 비워 둔 값을 하나씩 적고, 지표가 등록되었을 때 어떻게 정할지와 지금은 왜 정하지
못하는지를 나눈다. 6.2절은 프로필 열두 값을, 6.3절은 플랫폼이 고정한 규칙을 적는다. 능력 목록의 항목은
id로 가리키며, 능력 목록은 `.venv/bin/python -m trading_plugins.facts capabilities`로, 등록된 series
목록은 같은 명령의 `series`로 2026-09-28에 읽었다.

막힌 것을 `author-strategy` 절차의 세 갈래(빈 값, 재료 부재, 능력 부재)로 나누면 아래와 같다.

| 갈래 | 해당하는 것 | 능력 id 또는 근거 |
|---|---|---|
| 재료 부재 | 중앙 추세선(색상 상태 포함), 1차·2차 편차 밴드 네 줄, RSI 게이지(색상 상태 포함). 셋 모두 registry에 없고 계산식이 원문에 없다 | `series.sources`(series는 등록된 지표와 패턴뿐), `series.registration_unit`(등록되지 않은 조합은 선언할 수 없음), `registry.name_does_not_fix_definition`(이름이 비슷한 등록 series가 원문의 뜻을 계산한다고 볼 수 없음) |
| 능력 부재 | 1차 익절의 분할 청산(50%~80%)과 잔여 물량의 2차 청산 | `exit.partial`(청산은 전량이다) |
| 능력 부재 | 밴드 돌파 후 리테스트 최소 1회를 거친 재돌파 | `series.history_depth`(series는 판단 봉의 값 하나만 오고 전략은 상태를 갖지 못한다) |
| 능력 부재 | 의사코드의 `partial_tp_done` 상태 | `run.strategy_inputs`(포지션은 수량·진입가·leverage·청산가만 알려 주고 전략은 상태를 갖지 못한다) |
| 능력 부재 | 중앙 추세선 가격에 두는 손절 | `money_management.volatility_inputs_per_policy`(정책은 변동성 입력 하나를 반드시 선언해야 하므로 가격 수준 하나로 손절을 두는 정책은 만들 수 없다) |
| 빈 값 | 중앙 추세선의 색상 판정 규칙, RSI 게이지의 색상 판정 규칙, 밴드의 계산식과 기간·배수, 롱 돌파 대상 밴드("상단(또는 하단)"), 리테스트 횟수(1회 또는 2회), "비정상" 캔들 위치의 문턱, "강력한 추세 돌파"의 정의, 손절의 "부근"과 "직전 지지선·저항선", 손익비 1.5와 1.7 사이의 선택, 분할 비율 50%와 80% 사이의 선택, 종목, 시장 종류, leverage, 거래당 위험, 자료 구간, 수수료, 초기 자본, 프로필 열두 값 | 6.1절과 6.2절의 행마다 적는다 |

### 6.1 규칙의 빈 값

각 행의 "정한 값" 열은 두 가지 가운데 하나다. 지표가 등록되어 있었다면 이렇게 정했을 값과 그 근거를
적었거나, 지금은 정하지 않는 이유를 적었다. 정하지 않은 값은 지표를 등록하는 플랫폼 작업이 끝난 뒤 그
지표의 정의를 보고 다시 정해야 한다. 어느 것도 원문이 말한 값을 바꾸지 않는다.

| 비워 둔 값 | 정한 값 | 근거 |
|---|---|---|
| 중앙 추세선의 계산식 (원문 1절 「가격의 중심 추세를 나타내며」) | 정하지 않음 | registry에 없다. 가장 가까운 등록 series는 `Bollinger Bands`(period 20, multiplier 2.0)의 `middle` 출력(종가의 20봉 SMA, 지표 표준 `docs/references/technical_indicators_calc_spec.md` 3.10절)과 `Keltner Channel`의 중심(종가의 20봉 EMA, 같은 표준 3.2절)이지만 원문은 어느 것도 말하지 않고, "산점도/표준편차 알고리즘"이라는 서술은 회귀선 계열을 시사한다. 지표 표준에는 선형회귀 프리미티브(`LinRegForecast`, 부록)만 있고 그것으로 만든 중심선 지표는 등록되어 있지 않다. 등록 이름이 원문의 뜻을 계산한다고 볼 수 없다(`registry.name_does_not_fix_definition`) |
| 중앙 추세선의 색상 판정 규칙 (원문 1절 「상태에 따라 색상(초록색/보라색)이 변함」) | 정하지 않음 | 원문에 "상태"가 무엇인지 없다. 기울기의 부호인지, 가격과의 위치인지, 다른 지표와의 결합인지 알 수 없어 어느 하나를 고르면 원문에 없는 규칙을 지어내는 것이다 |
| 편차 밴드의 계산식과 기간·배수 (원문 1절 「4개의 편차 기반 밴드 (산점도/표준편차 알고리즘 기반)」) | 정하지 않음 | 두 단계(1차·2차) 밴드를 내는 등록 series가 없다. `Bollinger Bands`는 `period=20, multiplier=2.0` 한 조합만 등록되어 있어 한 쌍(상단·하단)만 내고, 1차 밴드에 해당할 다른 배수는 등록되어 있지 않다(`series.registration_unit`). `Keltner Channel`과 `Acceleration Bands`도 한 쌍뿐이다. 1차와 2차의 배수와 기간도 원문에 없다 |
| RSI 게이지의 계산식과 색상 판정 규칙 (원문 1절 「중앙 추세선 및 4개 밴드와의 비교 분석을 결합하여 상태를 자동 판별」) | 정하지 않음 | `RSI`(period 14)는 등록되어 있으나 원문의 게이지 색은 RSI 값의 문턱이 아니라 중앙 추세선·밴드와의 비교로 정해진다고 적혀 있고 그 비교 규칙이 없다. RSI 14에 30과 70 같은 문턱을 두는 것은 원문의 "연동형" 판정을 다른 규칙으로 바꾸는 것이라 하지 않았다 |
| 롱 돌파의 대상 밴드 (원문 3절 ① 2 「캔들이 상단(또는 하단) 1차 편차 밴드를 상향 돌파」) | 지표가 있다면 상단 1차 밴드 | 원문 3절은 "상단(또는 하단)"이라 적어 둘을 열어 두었고, 5절 의사코드는 `check_break_and_retest(bar, band_1st.upper, direction='BULLISH', min_tests=1)`로 상단 1차 밴드를 쓴다. 의사코드가 더 구체적이므로 그것을 따른다. 숏은 3절 ② 2와 의사코드가 모두 하단 1차 밴드로 일치한다 |
| "돌파"를 판정하는 가격 (원문 3절 ① 2 「캔들이 … 상향 돌파」) | 지표가 있다면 종가 | 원문은 고가인지 종가인지 말하지 않는다. 종가가 밴드 밖이면 고가도 밖이므로 종가 읽기가 더 적게 진입하는 보수적 읽기이고, 여섯째 회차(문서 06의 5.1절)와 같은 기준이다. 의사코드의 `bar.close`도 종가를 가리킨다 |
| 리테스트 횟수 (원문 3절 ① 3 「최소 1회(안정성을 높이려면 2회) 이상 지지」) | 지표가 있어도 판정하지 못함. 횟수만 정하면 1회 | 의사코드가 `min_tests=1`이다. 다만 횟수와 무관하게 "돌파한 뒤 리테스트를 거쳐 재돌파"는 앞 봉들의 밴드 값을 필요로 하는데 series는 판단 봉의 값 하나만 오고 전략은 상태를 갖지 못하므로(`series.history_depth`, `run.strategy_inputs`) 판정할 수 없다. 앞 봉들의 밴드를 판단 봉의 밴드 값으로 대신 읽는 근사는 승인이 필요한 종류라 지시 없이 택하지 않았다 |
| "지지 받는 봉"과 "N자형 눌림목 반등"의 정의 (원문 3절 ① 3) | 정하지 않음 | 저가가 밴드에 닿았다가 종가가 밴드 위로 돌아오는 봉으로 읽을 수 있으나 원문이 그렇게 말하지 않았고, 위 행의 이유로 어차피 판정하지 못한다 |
| "비정상" 캔들 위치의 문턱 (원문 2절 「캔들의 위치가 비정상적인 경우(예: 과매수 보라색 신호가 떴으나 캔들이 밴드 상단 위로 급등하는 등)」) | 정하지 않음 | 예시 하나뿐이고 "급등"의 기준이 없다. 예시대로라면 숏 환경에서 종가가 상단 밴드(1차인지 2차인지도 없음) 위에 있으면 보류하는 규칙이 되지만 원문이 그 문턱을 정하지 않았다 |
| "강력한 추세 돌파"의 정의 (원문 4절 ② 「1차 목표가 또는 강력한 추세 돌파 발생 시」) | 정하지 않음 | 정의가 없고, 이 조건이 촉발하는 분할 청산 자체가 `exit.partial`로 막힌다 |
| 손절의 위치 (원문 4절 ① 「중앙 추세선 라인 부근 또는 직전 지지선 하단」, 「중앙 추세선 라인 부근 또는 직전 저항선 상단」) | 정하지 않음 | 두 후보 가운데 어느 것을 언제 쓰는지, "부근"이 얼마인지, "직전 지지선"이 무엇인지 원문에 없다. 의사코드는 `sl_price = center_line`으로 중앙 추세선 값 자체를 쓰고 동시에 매 봉 `bar.close < center_line`이면 전량 청산한다. 어느 쪽이든 중앙 추세선이 등록되어야 하고, 가격 수준 하나로 손절을 두는 정책은 변동성 입력을 하나 선언해야 하는 규칙(`money_management.volatility_inputs_per_policy`) 때문에 만들 수 없다. 갖춰진 정책 셋(manual, turtle, signal-exit-atr)은 모두 ATR 또는 일간 N의 배수로 손절을 두므로 원문의 손절과 다르다 |
| 1차 목표 손익비 (원문 4절 ② 「1 : 1.5 (상황/직전 매물대에 따라 최대 1 : 1.7까지 유연하게 설정)」) | 지표가 있다면 1.5 | 의사코드가 `* 1.5`로 고정했다. "상황에 따라 1.7까지"는 재량이며 기계적 규칙이 아니므로 하한 1.5를 쓴다. 다만 원문의 R은 진입가에서 중앙 추세선까지의 거리이고 manual 정책의 R은 ATR 배수 거리라, `reward_risk` 1.5를 선언해도 목표가의 위치가 원문과 다르다(근사) |
| 1차 익절의 분할 비율 (원문 4절 ② 「포지션의 50% ~ 80% 분할 매도」) | 정하지 않음 | 의사코드는 0.80이지만 어떤 비율이든 `exit.partial`이 거짓이라 표현할 수 없다 |
| 2차 편차 밴드 "터치하거나 돌파"의 가격 (원문 4절 ② 「'2차 편차 밴드'에 터치하거나 돌파하는 즉시」) | 지표가 있다면 고가(롱)와 저가(숏), 의사코드대로 | 의사코드가 `bar.high >= band_2nd.upper`와 `bar.low <= band_2nd.lower`로 봉 안의 극값을 쓴다. 전략은 봉이 마감된 뒤 판단하므로 그 봉에서 "즉시" 팔 수 없고 다음 봉 시가에 체결된다(`run.fill_timing`). 2차 밴드 자체가 등록되어 있지 않다 |
| 진입 체결 시점 (원문 3절 ① 4 「양봉 완성 시 롱 포지션 오픈」) | 판단 봉이 마감된 뒤 다음 5분봉의 시가 | 플랫폼의 체결 시점이 `next_bar` 하나뿐이다(`run.fill_timing`) |
| 재진입 규칙 (원문에 없음) | 포지션이 없을 때마다 규칙을 그대로 평가한다 | 원문에 제한이 없다. 한 실행은 포지션을 하나만 들고 피라미딩이 없다(`run.concurrent_directional_positions`) |
| 종목 (원문에 없음) | 정하지 않음. 전략은 종목을 제한하지 않고 실행 설정이 고른다 | 원문에 종목이 하나도 없다. 한 실행은 종목 하나만 거래한다(`run.traded_symbols`) |
| 시장 종류 (원문에 없음) | futures 실행 | 원문이 롱과 숏을 모두 정의했다. spot 실행은 숏을 낼 수 없으므로 양방향을 재현하려면 futures 실행이어야 하고, 그때는 funding 정산이 더해진다 |
| Leverage (원문에 없음) | manual 정책 `leverage` 1(정책 기본값) | 원문에 없다. 가장 낮은 값이며, 원문이 주지 않은 값이므로 전략의 `default_settings`에 넣지 않는다(문서 06의 5.1절과 같은 판단) |
| 거래당 위험, 자료 구간, 수수료, 초기 자본 (원문에 없음) | 실행 설정이 정한다. 거래당 위험은 플랫폼 상한 1% 안에서 | 원문에 시험 조건이 하나도 없다. `risk.max_risk_per_trade`가 1%를 상한으로 고정한다 |
| 5분봉 자료의 유무 | 확인하지 않음 | timeframe 형식(`services/core-lib/core_lib/candles.py`의 `^[1-9]\d*[mhd]$`)은 `5m`을 받지만, 플랫폼 자료에 5분봉이 있는지는 능력 목록과 facts 명령이 말하지 않는다 |

### 6.2 프로필 값(`StrategyProfile` 열두 필드)

전략 클래스를 만들지 않았으므로 이 값을 담은 클래스는 없다. 그래도 지표가 등록된 뒤 만들 때 어디서
시작할지 남기기 위해 적는다. 원문에는 백테스트 결과가 하나도 없으므로 열두 값 모두 원문의 뒷받침이
없고, 뒷받침이 있는 것처럼 보이는 행도 규칙에서 간접적으로 끌어낸 것뿐이다.

| 필드 | 정한 값 | 원문의 뒷받침 |
|---|---|---|
| `id` | `orange-web3-band-retest-v1` | 없음(전략 식별자 `orange-web3-band-retest`에 판을 붙인 이름) |
| `family` | `trend` | 간접. 원문 3절이 밴드 돌파와 리테스트 뒤의 재돌파, 곧 추세 방향의 지속을 진입으로 삼는다. 원문이 이름을 붙이지는 않았다 |
| `bar` | `5m` | 원문 1절 「기본 주기(Timeframe): 5분봉(5m) 차트 기준」 |
| `expected_win_rate` | (0.35, 0.60) | 없음. 원문에 승률이 없다. 리테스트 확인을 거친 돌파 진입이라는 규칙의 성격만으로 넓게 잡은 잠정 범위다 |
| `expected_payoff` | (1.0, 1.7) | 상한만 간접. 원문 4절의 1차 목표 손익비 1.5와 최대 1.7이 비용 전 상한이다. 분할 청산과 2차 밴드 청산이 있으면 실제 payoff는 그보다 클 수도 작을 수도 있고, 하한은 뒷받침이 없다 |
| `tail_shape` | `symmetric` | 없음. 원문의 분포 자료가 없다 |
| `holding_horizon` | `intraday` | 간접. 5분봉에서 1.5R 목표와 2차 밴드 도달로 닫는 규칙이므로 하루를 넘기는 보유는 드물 것이라는 판단이며 원문의 자료는 없다 |
| `primary_metric` | `pf` | 없음. 원문에 결과 지표가 없어 앞선 회차와 같은 값을 둔다 |
| `risk_adjusted_pref` | `sortino` | 없음 |
| `profit_structure_to_preserve` | `band-break-retest-with-partial-target` | 없음(규칙을 요약한 이름) |
| `envelope_tolerance` | 0.20 | 없음(앞선 여섯 전략과 같은 값) |
| `envelope_status` | `provisional` | 규범 4.1절이 새 전략에 고정한 값 |

### 6.3 플랫폼이 고정한 규칙

원문이 정하지 않았거나 다르게 정한 것 가운데 플랫폼이 바꿀 수 없게 고정한 규칙이다. 이 전략에서는
고정된 규칙이 원문의 규칙을 막는 자리가 넷 있어(분할 청산, 리테스트 판정, 청산 상태, 가격 수준 손절),
그 넷은 7절에서 "플랫폼 고정"이 아니라 "능력 부재로 강제됨"으로 적는다.

| 규칙 | 플랫폼의 값 | 능력 id | 이 전략과의 관계 |
|---|---|---|---|
| 청산의 단위 | 청산은 포지션 전량이다. 일부만 닫고 나머지를 두는 것은 표현할 수 없다 | `exit.partial` | 원문 4절 ②의 분할 청산(50%~80% 뒤 잔여 20%~50%)을 막는다 |
| 전략이 보는 series 이력 | 이번 봉의 값 하나만 온다. 직전 봉의 밴드 값은 오지 않고 전략은 상태를 갖지 못한다 | `series.history_depth` | 원문 3절의 "돌파 후 리테스트 후 재돌파" 순서를 막는다. 캔들은 전부 오므로 캔들끼리의 비교는 되지만 앞 봉의 밴드 값이 없다 |
| 전략이 받는 입력 | 여섯 key와 현재 포지션뿐이다. 포지션은 수량·진입가·leverage·청산가만 알려 준다 | `run.strategy_inputs` | 원문 5절 의사코드의 `partial_tp_done` 상태를 둘 곳이 없다 |
| 정책의 변동성 입력 | 정책은 변동성 입력을 정확히 하나 선언해야 한다 | `money_management.volatility_inputs_per_policy` | 원문 4절 ①의 중앙 추세선 가격 손절처럼 시장 변동성이 아닌 가격 수준으로 손절을 두는 정책을 만들 수 없다 |
| 보호가격의 수정 | 정책은 진입 때 한 번 계획하고 손절·목표를 뒤에 옮기지 않는다 | `money_management.protection_fixed_at_entry` | 원문은 손절 이동을 말하지 않으므로 직접 막는 것은 없다. 다만 1차 익절 뒤 잔여 물량의 손절을 옮기는 관행이 있어도 표현할 수 없다 |
| 추적 손절 | 없다 | `exit.trailing_stop` | 원문은 추적 손절을 말하지 않는다. 기록만 한다 |
| 판단이 체결되는 시점 | 마감 봉에서 판단하고 다음 봉에 체결한다 | `run.fill_timing` | 원문 3절의 "봉 완성 시 오픈"은 다음 5분봉 시가 체결이 되고, 4절 ②의 "터치하는 즉시 전량 매도"도 전략 청산으로 내면 다음 봉 시가 체결이 된다 |
| 전략을 부르는 시점 | 실행 timeframe의 확정 봉마다 한 번 | `run.decision_trigger` | 원문 5절 「5분봉 캔들 갱신 시 실행」을 봉 마감 시로 읽는다 |
| 보호가격을 검사하기 시작하는 봉 | 체결한 봉에서는 손절·목표·강제청산을 검사하지 않고 다음 봉부터 검사한다 | `execution.protection_checked_from_bar_after_fill` | 원문에 없다 |
| 한 봉이 손절과 목표에 모두 닿을 때 | 손절로 닫는다 | `execution.simultaneous_stop_and_target` | 원문에 없다 |
| 한 실행이 드는 포지션 수 | 방향 포지션 하나. 같은 방향의 두 번째 진입은 `pyramiding_disabled`로 건너뛴다 | `run.concurrent_directional_positions` | 원문에 없다 |
| 거래당 위험 상한 | 자기자본의 1% | `risk.max_risk_per_trade` | 원문에 거래당 위험이 없다 |
| 한 실행이 거래하는 종목 수 | 하나 | `run.traded_symbols` | 원문에 종목이 없다 |
| 선언할 수 있는 series | 등록된 지표 조합과 캔들 패턴뿐이며, 등록 이름이 원문의 뜻을 계산한다는 보장은 없다 | `series.sources`, `series.registration_unit`, `registry.name_does_not_fix_definition` | 원문 1절의 세 구성 요소가 모두 여기에 걸린다 |

## 7. 원문 대비 차이 기록표

규범 6.6절의 네 열과 여섯 종류를 쓴다. 전략을 구현하지 않았으므로 "플랫폼 표현" 열은 지표가 등록되었을
때 표현할 것을 적거나, 표현할 수 없으면 "없음"을 적는다. 승인이 필요한 종류(능력 부재로 강제됨,
근사함)의 행은 이번 회차에 답할 사람이 없어 근거 열에 "승인 대기(지시에 따라 진행)"를 적었고, 여기서
"진행"은 구현이 아니라 기록과 보고를 뜻한다. 원문이 말하지 않은 것(체결 시점, 프로필 값)도 행으로
